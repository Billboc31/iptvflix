## Objective

Add a typed, migration-driven PostgreSQL persistence layer to the `api` package using Drizzle ORM and Drizzle Kit, so that all future domain features (catalog, profiles, history, recommendations) share a single, reproducible data-access foundation.

## Included

### Dependencies (`api/package.json`)
- Add runtime deps: `drizzle-orm`, `postgres` (postgres.js driver), `dotenv`
- Add dev deps: `drizzle-kit`

### Docker Compose (`docker-compose.yml`, root)
- `postgres` service: image `postgres:16-alpine`, named volume `pgdata`, port `5432`, healthcheck (`pg_isready`), env vars `POSTGRES_USER / POSTGRES_PASSWORD / POSTGRES_DB` with local-dev defaults

### Environment config
- `api/.env.example` — documents `DATABASE_URL=postgres://iptv:iptv@localhost:5432/iptvflix`
- `api/.env` — gitignored, filled by developer from `.env.example`

### Drizzle config (`api/drizzle.config.ts`)
- Points schema to `src/db/schema/**/*.ts`, migrations output to `migrations/`, driver `postgres-js`
- Reads `DATABASE_URL` from `process.env`

### DB client (`api/src/db/client.ts`)
- Creates and exports the `postgres()` connection pool and the `drizzle(pool)` instance
- Throws a sanitized `Error("Missing DATABASE_URL")` if the env var is absent (no credential leakage)

### Schema convention (`api/src/db/schema/index.ts` + `api/src/db/schema/app_config.ts`)
- `app_config` table: `id serial PK`, `key text UNIQUE NOT NULL`, `value text`, `created_at timestamp DEFAULT now()`
- Chosen as the minimal initial migration target; it proves the full schema→migration round-trip without introducing domain tables
- `schema/index.ts` re-exports all table definitions (convention for future tables)

### Initial migration (`api/migrations/`)
- Generated by `pnpm drizzle-kit generate` and committed; must be reproducible from a clean checkout

### Health check (`api/src/db/health.ts`)
- `checkDatabaseHealth(): Promise<{ ok: boolean; latencyMs?: number; error?: string }>`
- Runs `SELECT 1` with a timeout; catches errors and returns `{ ok: false, error: "Database unreachable" }` — never surfaces the connection string

### npm scripts (`api/package.json`)
- `db:generate` → `drizzle-kit generate`
- `db:migrate` → `drizzle-kit migrate`
- `db:studio` → `drizzle-kit studio`

### Tests (`api/src/db/__tests__/health.test.ts`)
- Integration test (requires running Postgres, skipped in CI without `DATABASE_URL`): asserts `checkDatabaseHealth()` returns `{ ok: true }`
- Unit test for the missing-env-var guard: sets `DATABASE_URL` to `undefined`, asserts the client constructor throws the sanitized message

### Local dev documentation (`docs/local-dev.md`)
- `docker compose up -d` to start Postgres
- Copy `.env.example` → `.env`
- `pnpm --filter api db:migrate` to apply migrations
- `pnpm --filter api db:generate` to regenerate after schema changes

## Excluded

- Any IPTVFlix domain tables (channels, sources, profiles, history, recommendations) — tracked in T003 and later tickets
- Redis, BullMQ, or any job queue infrastructure
- Production database hosting or cloud provisioning
- Drizzle query builder usage beyond the health check — repositories for domain entities belong to their own tickets
- HTTP endpoint for the health check — only an internal function is provided here

## Acceptance criteria

- `docker compose up -d && pnpm --filter api db:migrate` succeeds on a clean checkout with no prior state
- `pnpm --filter api db:generate` produces no diff when run against the committed schema (migrations are in sync)
- `checkDatabaseHealth()` returns `{ ok: true, latencyMs: <number> }` when Postgres is reachable
- `checkDatabaseHealth()` returns `{ ok: false, error: "Database unreachable" }` (no URL in message) when Postgres is down
- The client module throws `Error("Missing DATABASE_URL")` when the env var is absent
- All tests pass: `pnpm --filter api test`
- `docs/local-dev.md` exists and covers Docker startup, env file setup, and migration commands
- No domain tables are introduced; the only schema object is `app_config`
